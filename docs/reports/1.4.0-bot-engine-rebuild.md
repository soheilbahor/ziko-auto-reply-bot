# ZIKO 1.4.0 — Bot Engine Rebuild

## Scope
This update builds on the uploaded 1.3.0 source. It does not claim a full rewrite of Telegram's platform integration.

## Included
- Per-tenant database isolation remains in place: each child bot uses its own SQLite database and owner allow-list.
- Telegram Business connection updates are validated against the configured owner and persist explicit enabled/can-reply permissions.
- Business replies remain gated on an enabled connection, explicit `can_reply`, active auto-reply state and a private non-bot customer message.
- Delivery deduplication and at-most-once protection remain enabled.
- Added privacy-preserving delivery statistics to the existing statistics screen.
- Added owner-only `/health` diagnostics for the child bot.
- Hardened handling of incomplete inbound Business message objects.
- Added a storage statistics test.

## Not changed
- The product still uses the existing predefined status set; this update does not add arbitrary user-created status categories.
- It still sends the selected static status text; it is not an AI conversational agent and does not generate context-aware answers.
- A real Telegram Business account and the target bot must be used to verify connection permissions and actual reply delivery.

## Validation performed
- Python compileall: passed.
- `bash -n` across shell scripts: passed.
- pytest collection: blocked because `aiosqlite` and `aiogram` are not installed in the build environment.
- No live Telegram, webhook, Business account, or Ubuntu systemd test was performed.
