# ZIKO 1.3.0 — Core update report

## Source examined
The supplied `ziko-assistant-1.2.2-single-version-source` archive (85 files; VERSION 1.2.2).

## Changes in this build
- Tenant poller manager now has an explicit closing state. New pollers are rejected once shutdown begins, supervisors leave their restart loop, and child tasks are cancelled and awaited with a bounded timeout.
- Child dispatchers no longer install process signal handlers. The root dispatcher remains the process-level signal owner.
- Managed-bot credential rotation stops the previous poller before replacing the stored encrypted credential, preventing a stale Unauthorized response from disabling the replacement token.
- Expired Telegram callback-query answers are handled as stale UI interactions; unrelated TelegramBadRequest exceptions still propagate.
- Old inbound update identifiers are pruned on startup. Default retention is 30 days and `ZIKO_EVENT_RETENTION_DAYS` accepts 1–365. Message bodies remain unpersisted.
- systemd receives an explicit 35-second stop budget; tenant poller cleanup is bounded to 20 seconds.
- Version marker, changelog and operational notes updated to 1.3.0.

## Deployment recommendation
Deploy to a staging copy first. Confirm `/tenants` runtime states, rotate a managed bot token in a controlled test, and run `systemctl stop ziko` while observing that the service exits cleanly without child poller restarts or SIGKILL. Keep a verified encrypted backup of the tenant registry database and `tenant-token.key` together before upgrading.
